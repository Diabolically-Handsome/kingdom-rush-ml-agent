## 3. 人类玩家的打法

以下来源由研究代理检索。fandom 页面直接访问返回 HTTP 402，只看到搜索摘要，可信度较低；Steam “100% Veteran” 指南只看到摘要（HTTP 429）。

**第 20 关**

## 4. 方案

### 4.1 总规则（所有阶段都适用）

1. **G0 之前什么都不做。**
   - 除本文件外，不写开发代码，不跑开发副本或探针局，不运行 kh.py，不运行配置构建器——除非您另外批准某一项更窄的只读准备工作。
   - G0 的开工条件：
     - 账本里彩排 2 有收账行；
     - 一次性最终评测也有收账行。如果最终评测被推迟、取消或中止，由您明确决定 8001–8005 是否继续保留、elite-v2 能否开始；
     - 所有 `runtime/rl/*/job.lock` 都不存在；
     - 您给出新的书面同意，并把原话写进每个作业的批准字段。
   - **绝不根据时钟推断 G0 已满足。**
2. **一次只运行一个作业，跨阶段也一样。**
   - 现在的预检只看本阶段的锁和全局 `runtime/rl/job.lock`（`phase.py:289-293`），看不到 elite-v1 的锁。elite-v2 冻结前，把预检改成：只要存在任何 `runtime/rl/*/job.lock` 就拒绝。所有配置构建器和临时工具也做同样的检查。
   - 账本作业之外的游戏运行（宿主冷重放、开发副本神谕），必须同时满足：经您批准、先做锁检查、使用 9950 以上的端口、只用训练种子（冷重放除外）、写入日志。
3. **静音。** 每一次游戏启动，不论是作业还是临时运行，都要用 `rng_mode="isolate_sound+stable_pairs"`：
   - 引擎默认是空字符串，会出声音（`engine.py:269, 287`）；
   - 每个新工具在第一局之前都要断言这一点，并照 REPORT.md:499 的做法，抽查一次没有游戏进程加载 AudioSes/MMDevAPI/dsound。
4. **8B 与 GPU。**
   - 只在您授权的 5090 窗口里调用 8B 服务（127.0.0.1:12081，`campaign-survey.py:52`）。
   - 使用前先确认 5090 空闲（REPORT.md:194；不抢占另一个项目的进程，REPORT.md:125）。
   - 服务必须用 `model-worker.py --gpu 5090` 启动（默认映射是 5080，`model_broker.py:21-22`；REPORT.md:502 规定 5080 不动）。
   - 除了这些窗口，任何代码级别的检查都只用离线提示词哈希。
5. **不改变任何现有基因的含义。** 新基因一律是可选的、取默认值时不写入，所以已有计划的 genome_id 和兜底规则名都不变。L15 依赖 boss=1（10 个战役计划中有 9 个用它）。新基因的变异、移民比例都用按关卡生效的配置键控制，不修改 `IMMIGRANTS=0.10` 这类常量。
6. **快照与回滚。** 项目不是 git 仓库，pins 只记哈希。所以：
   - G0 后第一件事，是把 elite-v1 冻结时的 70 个钉住文件复制到带日期的存档，并逐一对照 pins.json 校验；
   - 之后每次移植前都再做一次快照；
   - 一致性检查失败时，恢复快照，修好之前不跑任何作业。
7. **预先登记统计规则**（每个门槛都按这个规则判）：
   - **配对单位**：同一存档、同一种子上，只差一个基因的两个计划（配对双胞胎）。引擎是确定性的（`campaign_run.py:361`）。两局的 trace 哈希若相同，说明这个基因没起作用，这一对不计入，单独报告。
   - **主指标**：死亡波次（赢记为 16）。先按种子把各计划的差值取平均，得到 20 个种子级差值，再做**精确符号翻转置换检验**（单侧 α=0.05）。这样处理是因为多个计划共用同一批种子，结果不独立（种子间 Spearman 0.43）。
   - **胜场**：对结果不一致的配对做精确单侧符号检验，需要 ≥5/5、≥7/8、≥9/10、≥10/12 或 ≥12/15。
   - **不退步**：种子级平均差的 95% 下界 ≥ -0.3 波，且 W4/W6/W8 开始时的生命中位数不下降超过 1。
   - **最小可检测效应**：B 块开始前，用 WS2 测得的种子间方差计算。粗估约 0.9 波【假设：种子级差值标准差约 1.5 波】。如果算出来超过 1 波，就增加计划数，不动用留出区。
